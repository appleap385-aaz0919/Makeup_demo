컬러매치 웹 메이크업 — 2026-11-24

실행
- Node.js가 설치된 환경에서 npm start를 실행한 뒤 http://127.0.0.1:4173 에 접속한다.
- npm 설치나 API 키는 필요 없다. 서버는 로컬 파일을 제공하는 용도로만 사용한다.
- 정적 파일이므로 외부 웹 서버에 그대로 배포할 수도 있다.
- 샘플 사진과 사용자 사진 모두 MediaPipe 모델로 분석한다. 미리 그린 샘플용 마스크는 제거했다.
- 모델과 실행 파일을 vendor/vision에 배치했다. 현재 구성에서는 로컬 정적 파일만 받아 실행한다. 이 폴더가 없을 때만 CDN과 Google 모델 저장소에서 받는다. 사진 자체를 보내는 API 호출은 하지 않는다.
- 네트워크가 가능한 환경에서 npm run prepare:models를 실행하면 vendor/vision에 실행 파일과 모델을 저장한다. ready.json이 있으면 외부 CDN 대신 로컬 파일을 사용한다. 실행 중인 서버는 모델 배치 후 재시작한다.

화면 흐름
1. 샘플 사진에서 바로 시작하거나 사진 바꾸기를 누른다.
2. 피부 / 립스틱 / 블러셔 / 눈 화장 / 헤어 중 하나를 선택한다.
3. 색상과 적용 강도를 변경한다. 다른 탭으로 이동해도 선택값을 유지한다.
4. 원본 보기 또는 구분선을 움직이는 전후 비교로 확인한다.
5. 확인 가능한 결과 이미지를 PNG로 저장한다. 사용자 사진은 처리 메모리를 줄이기 위해 긴 변 최대 1600px로 합성·저장한다.

부위별 조작
- 파운데이션: 24색. 밝기 8단계 × 뉴트럴·쿨·웜. 톤별 필터를 제공하고 동일한 합성 비율로 호수를 비교한다. 강도 슬라이더는 제공하지 않는다.
- 립스틱: 48색 + 계열 필터 + 직접 색상 선택 + 미적용 + 강도 + 매트/글로시.
- 블러셔: 36색 + 계열 필터 + 직접 색상 선택 + 미적용 + 강도 + 범위.
- 아이라이너: 검정색 ON/OFF + 두께 + 꼬리 길이 + 색상 진하기 + 방향(-35~45도).
- 아이섀도: 매트·글로시 각 48색 팔레트 + 계열 필터 + 직접 색상 선택 + 미적용 + 자체 적용 강도 + 눈두덩이 상하 폭·좌우 폭. 기본 강도는 55%이며, 색상 합성에 불투명도 합성을 더해 발색을 보강한다. 눈두덩이 위쪽으로 갈수록 색을 옅게 하고 적용 높이에 맞춰 외곽을 부드럽게 처리한다. 눈 안쪽은 경계를 부드럽게 처리한 후에도 적용 영역에서 제외한다. 글로시는 눈두덩이 마스크 안에 부드러운 반사광을 추가한다.
- 애교살: ON/OFF + 자체 진하기 + 위치 미세 조절. 원본 명암을 위치 추정에 활용하며 밝은 효과와 얇은 음영을 함께 표시한다.
- 헤어: 18색 + 내추럴·브라운·애쉬·포인트 필터 + 직접 색상 선택 + 미적용 + 강도.
- 점: 피부 메뉴에서 최대 3개 배치, 선택, 크기, 드래그 및 화살표 이동, 삭제와 초기화를 제공한다. 사진 좌표로 저장하므로 확대·축소 상태에서도 위치가 일치한다. 편집용 표시와 터치 영역은 저장 이미지에 포함하지 않는다.
- 렌즈: 눈 화장 안에서 12색, 발색, 테두리 진하기를 제공한다. 홍채와 눈꺼풀 마스크를 교차하고 추정 동공 중심부와 밝은 반사광을 제외한다. 실제 동공 분할 모델은 아니며 어두운 사진·가림·큰 시선 변화에 대한 실사진 검증은 더 필요하다.
- 색상 계열과 아이섀도 질감은 제목 행의 네이티브 선택 메뉴로 압축해 모바일에서 색상칩을 먼저 볼 수 있게 한다. 선택 메뉴 글자는 iOS의 입력 확대를 피하도록 16px를 사용한다.
- UI 참고: 기존 screenshots/mobile-gloss-palette.png, mobile-lenses.png, mobile-beauty-marks.png를 보고 필터 행을 줄였다. 상위 탭 5개와 고정 사진·크기 조절 패널을 유지한다.
- 홍채 좌표 출처: https://github.com/google-ai-edge/mediapipe/blob/master/mediapipe/tasks/web/vision/face_landmarker/face_landmarks_connections.ts
- 추가 검증: 실제 모델로 같은 강도에서 아이섀도 발색 증가, 매트/글로시 차이, 눈 안쪽 제외, 아이라이너 꼬리 방향 변화, 홍채 밖 색상 누출 없음, 동공 중심부 보존, 점 크기 변화를 확인한다. UI에서는 계열별 색상 선택, 렌즈 독립 초기화, 점 3개 제한·배치·크기·드래그·화살표·삭제·실행 취소, 확대 화면의 점 좌표 일치, 새 사진에서 이전 점 위치 제거를 검사한다. 모바일 실기기와 다양한 조명·가림·시선에 대한 추가 검증은 필요하다.
- 초기 색상표는 UI 검토용 자체 가상 색상이며 실물 제품 대응값이 아니다.

반응형 배치
- PC: 왼쪽에 큰 사진, 오른쪽에 메이크업 패널.
- 모바일: 화면 높이 안에서 사진과 하단 메이크업 패널을 함께 표시한다. 전체 페이지를 스크롤하지 않는다.
- 사진과 전후 비교 도구는 계속 보인다. 색상표가 긴 경우 하단 패널 내부만 스크롤한다.
- 하단 패널은 화면 높이의 약 46%를 사용한다. 5개 부위 탭과 저장 버튼은 패널 안에 고정한다.
- 높이가 작은 가로 화면에서는 사진과 패널을 좌우로 배치한다.
- 적용한 부위는 탭에 표시하고 현재 조합은 저장 버튼 위에 요약한다.
- 부분 초기화, 전체 초기화, 실행 취소를 제공한다.
- 메이크업 패널의 장식용 제목과 부위별 소개 문구를 제거해 색상표에 공간을 배정한다.
- 부위별 초기화는 색상표 제목 옆에 둔다. 눈 화장은 다른 눈 효과도 함께 초기화된다는 점을 버튼에 명시한다.
- 실행 취소·전체 초기화는 PC·태블릿에서 팔레트 위 오른쪽에 배치한다. 좌우 배치에서는 사진 위 오른쪽의 확대·사진 바꾸기와 행을 맞추고, 세로 태블릿의 위아래 배치에서는 팔레트 바로 위 오른쪽의 별도 줄을 사용한다. 테두리 없는 텍스트 도구와 44px 조작 영역을 유지한다. 모바일 배치는 변경하지 않는다.
- 사진 상단에 확대/축소 버튼을 추가한다. 확대 시 전용 보기에서 사진을 화면 너비의 96%로 표시하고, 사진이 화면 높이보다 크면 사진 영역만 스크롤한다.
- 확대 상태에서도 비교 도구와 축소 버튼은 보인다. 축소 또는 Escape로 돌아오면 메이크업·비교 위치·선택 탭·패널 스크롤 위치를 유지한다.
- 서비스의 주 색상은 진한 보라색 #5B21B6이다. 로고, 저장 버튼, 선택 메뉴, 토글, 슬라이더, 선택 테두리에 적용한다. 가상 메이크업 팔레트의 색상은 바꾸지 않는다.
- 탭 방향키 이동, 버튼 선택 상태, 스위치 상태, 결과 알림, 포커스 표시를 제공한다.

현재 구현
- 기본 샘플도 실제 모델로 인식해 피부·입술·눈·헤어 영역을 생성한다.
- 사용자 JPG/PNG/WebP 사진을 기기에서 읽어 보여준다.
- 기기 내 얼굴 좌표 인식, 피부·헤어 분할, 영역 기반 합성을 실제 Chrome 브라우저에서 확인했다. 입 안과 치아를 립스틱 영역에서 제외한다.
- 사용자 사진을 서버에 업로드하거나 저장하지 않는다.

아직 구현하지 않은 것
- 다양한 피부색·얼굴 각도·기존 화장·촬영 조건과 모바일 실기기에서의 품질 검증. 현재 검증 입력은 기본 샘플과 추가 인물 사진, 그리고 회전·축소·복수 얼굴·빈 이미지 등으로 제한된다.
- 가림을 직접 분류하는 모델. 현재는 좌표와 기하 구조가 불확실한 부위만 제한한다. 안경, 마스크, 손, 앞머리로 가려진 부위를 항상 식별하는 것은 아니다.
- 헤어의 밝은 탈색, 경계 잔머리, 가림, 기존 화장 처리.
- 본 서비스의 색상표 최종 확정.

본 구현 구조
- MediaPipe FaceLandmarker와 SelfieMulticlass ImageSegmenter를 기기에서 실행하도록 연결한다. SDK 버전은 0.10.32로 고정한다.
- 메이크업 합성은 기기의 그래픽 코드로 수행한다. 생성형 AI API는 사용하지 않는다.
- 웹은 정적 호스팅에서 코드·실행 라이브러리·모델을 배포한다. 오프라인 지원에는 캐시 처리가 추가로 필요하다.
- 네이티브 앱은 모델을 앱에 포함할 수 있다.
- 촬영 환경과 원본 색상은 보정하지 않는다.
- 실시간 카메라 체험은 정지 사진 기능 이후의 확장 과제이다.

사진 예외 처리
- 얼굴 없음: 다른 사진 선택을 안내하고 합성·저장을 제한한다. 마지막으로 사용하던 얼굴 마스크를 새 사진에 재사용하지 않는다.
- 여러 얼굴: 첫 번째 얼굴을 임의로 선택하지 않고 한 사람만 나온 사진을 안내한다.
- 얼굴 크기 부족, 잘린 얼굴, 큰 좌우·위아래 각도: 적용을 중단하고 구체적인 사진 선택 방법을 안내한다.
- 가벼운 기울임: 눈 사이의 축을 기준으로 합성 위치를 계산한다. 정상 범위의 기울임을 이유로 무조건 차단하지 않는다.
- 눈 또는 입술 좌표 불확실: 해당 부위만 제한한다. 눈을 감은 것으로 추정되는 기하 구조는 눈 화장만 제한한다.
- 피부·헤어 분할 모델 준비 실패: 다른 부위는 유지하고 해당 기능만 제한하며 다시 시도를 제공한다.
- 헤어 영역 부족: 헤어 기능만 제한한다.
- 모델 로딩 실패·시간 초과·브라우저 미지원: 사진 문제와 구별해 안내한다. 지원되는 경우 다시 시도, 다른 사진 선택, 샘플로 돌아가기를 제공한다.
- 손상된 파일, 지원하지 않는 형식, 20MB 초과: 기존 사진을 유지하고 이유를 알린다.
- 사진을 바꾸거나 샘플로 돌아가면 이전 분석 결과를 무시한다. 이미지 저장 시에는 저장 버튼을 누른 시점의 사진과 메이크업 조합을 사용한다.
- 조명이나 원본 색상을 자동 보정하거나 촬영 환경을 이유로 제한하지 않는다.

검증 범위
- npm test: 합성 좌표로 만든 정상·비정상 입력에 대한 판정 로직 11개 테스트.
- 브라우저: 기존 UI, 확대/축소, 비교, 저장과 함께 모의 모델 결과로 얼굴 없음/여러 얼굴/옆얼굴/작은 얼굴/잘림/모델 오류/부분 제한/재시도/늦은 결과 취소/손상 파일 처리를 확인한다.
- 모의 모델 결과를 사용한 UI 검증은 실제 사진에서의 모델 정확도 검증과 다르다. photo-no-face.png 등 오류 화면의 얼굴 사진은 모의 결과를 시험하기 위한 입력이다.
- node scripts/verify-real.mjs: 실제 MediaPipe 모델로 기본 샘플과 추가 인물 사진의 인식, 모든 메이크업 부위 사용 가능 여부, 픽셀 변경, 치아 제외, 전후 비교, 모바일 크기 배치를 확인했다.
- 실제 모델로 빈 이미지와 복수 얼굴을 차단하고, 작은 얼굴을 적용 불가로 처리하며, 15도 기울인 얼굴을 정상 처리하는 것을 확인했다. 너무 작은 얼굴은 모델이 검출하지 못해 얼굴 없음으로 안내될 수 있다.
- 준비된 로컬 모델을 사용할 때 외부 HTTP 요청과 사진 전송 요청이 없는 것을 브라우저 네트워크 기록으로 확인했다.
- screenshots/real-makeup.png, real-makeup-mobile.png, real-compare-expanded.png, real-no-face.png와 real-verification.json에 결과를 저장했다.
- 실제 모바일 기기, 큰 좌우·위아래 각도, 안경·마스크·손·앞머리 가림은 추가 검증이 필요하다. 정적 호스팅을 떠난 완전한 오프라인 PWA 실행은 아직 구현하지 않았다.
- 아이섀도 최대 상하·좌우 폭에서 검출된 눈 영역 내부의 마스크 알파가 0인지 검사한다. 경계 흐림 이후 눈 마스크를 제외하며, 제외 처리에 흐림 필터가 다시 적용되지 않도록 필터 상태를 복원한다. 실제 얼굴 좌표 검출 오차는 별도 한계로 남는다.

눈 화장과 범위 옵션 개선 (2026-11-24)
- 기존 검증 캡처 screenshots/mobile-eyes.png에서 두 토글·애교살 슬라이더가 색상표를 아래로 밀어내는 구조를 확인했다. 기존 보라색 테마와 고정 사진 영역은 유지한다.
- 상위 탭은 5개를 유지한다. 피부 안에는 파운데이션 / 점을, 눈 화장 안에는 아이섀도 / 아이라이너 / 애교살 / 렌즈를 두고 선택한 기능만 표시한다.
- 하위 메뉴는 기능을 켜는 버튼이 아니라 편집 대상 선택이다. 각 기능 적용은 독립적이고, 적용 표시는 작은 점으로 남긴다. 기능별 초기화는 다른 눈 화장을 보존한다.
- 파운데이션 강도 UI와 상태를 제거했다. 렌더러는 호수에 관계없이 0.14의 동일한 색상 합성 비율을 사용한다. 실제 제품 커버력이나 측색 정확도를 의미하지 않는다.
- 아이라이너: 두께, 꼬리 길이, 검정색 진하기를 조절한다. 마스크는 눈꺼풀 바깥쪽에 생성하며 안쪽은 가늘고 바깥쪽은 두꺼워진다. 경계는 흐리게 처리한다.
- 블러셔: 기본 영역을 확장하고 범위 슬라이더를 제공한다. 얼굴 피부 마스크가 있으면 피부 밖으로 번지는 것을 제한한다.
- 애교살: 양쪽 눈별로 원본 명암의 어두운 골 후보를 제한된 범위 안에서 찾는다. 후보 3개 이상이 모이는 경우만 활용하며 불확실하면 가까운 눈 아래 윤곽을 기준으로 배치한다. 위아래 위치를 수동으로 보정할 수 있다. 명암 휴리스틱이므로 주름이나 눈 밑 그늘을 잘못 찾을 수 있고 원래 애교살에 정확히 맞춘다는 보장은 없다.
- MediaPipe 공식 설명의 478개 랜드마크는 얼굴 좌표이며 애교살 전용 분할 결과가 아니다. PSGAN은 참고 사진의 메이크업을 전이하는 별도 연구 모델이며, 이번 옵션용 모델로 연결하지 않았다.
- 출처: https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker
- 연구 모델 참고: https://github.com/wtjiang98/PSGAN
- 범위 확장: 아이섀도 기본 상하·좌우 폭은 50%, 각각 독립 조절한다. 아이섀도 초기화와 실행 취소에 포함되고 하위 메뉴 전환 시 유지한다. 아이라이너 꼬리 최대 길이는 눈 가로 길이의 0.36배에서 0.60배로 확장했다. 애교살 아래 위치 최대 이동은 눈 가로 길이의 0.10배에서 0.16배로 확장했으며 자동 위치 0%와 위쪽 이동은 유지했다.
